# Sprint 2 Intelligence Layer: state machines, smart retry, failure learning, watchdog, and 4-layer memory

Six features land the "intelligence" substrate for NEXUS: a phase machine gates leader-driven workflows through CREATE→DESIGN→EXECUTE→COMPLETE with an explicit human approval step; smart retry wraps the existing `RetryWithBudget` with error-pattern tracking and escalation (REPORT_BLOCKER, REASSIGN, DECOMPOSE); failure alchemy transforms errors into Antibody/Vaccine/Catalyst learning artifacts using regex heuristics; a watchdog performs periodic patrol recovering stuck, orphaned, budget-exceeded, and circuit-broken agents; a 4-layer memory system (L0 ephemeral, L1 session ring, L2 per-agent facts with Jaccard dedup, L3 shared organizational knowledge) adds structured knowledge management; and an Alembic migration closes the circuit_breaker_records table gap. All 151 new tests pass.

Watch for: Promotion engine declares a `min_age_hours` criterion but never enforces it, so freshly-created facts can be promoted immediately (confirmed). The `agents_provider` parameter in `Watchdog.start_background_patrol` is typed `Any`, losing all type safety on the callable shape (confirmed). Smart retry charges `estimated_cost_per_attempt_cents` for failed attempts even though no real cost was incurred from `execute_fn`, which can trigger budget-exhaustion stops prematurely when the estimate is inaccurate (confirmed).

**Verdict**: APPROVED

## High-level view

The phase machine is a minimal, in-memory, per-leader state tracker that enforces a fixed 4-phase cycle via explicit transition methods. There's no persistence or event emission, so leader state is lost on process restart.

Smart retry extends `RetryWithBudget` semantically rather than via inheritance — it replicates the budget-check-and-loop pattern with an added `Counter`-based diagnosis step. The early-exit on permanent blocker detection avoids wasting budget, though the cost model assumes every failed attempt costs the estimated amount regardless of whether execution actually consumed resources.

Failure alchemy applies eight regex patterns against error messages to produce Antibody rules, Vaccine test scenarios, and (after three occurrences of the same pattern category) Catalyst improvement proposals. The generated artifacts are generic templates — the antibody rule for a timeout is always "Never run {action} without setting a timeout guard" — which means value depends entirely on the `context["action"]` string being specific enough to be actionable.

The watchdog separates patrol logic (synchronous, pure) from scheduling (async `_patrol_loop`). Circuit state is injected via `set_circuit_states` rather than queried live, so the patrol acts on a snapshot that may be stale by the time actions execute. The `agents_provider` parameter is typed `Any`, meaning callers can pass the wrong callable shape without lint warnings.

The 4-layer memory system introduces Jaccard-based dedup (threshold 0.8), a promotion engine that checks access count OR cross-agent validation, and a ring buffer for session summaries. The `PromotionEngine.should_promote` ignores the `min_age_hours` field it declares, making premature promotion possible.

## Smart retry cost model and early-exit behavior

The `execute_with_smart_retry` loop charges `estimated_cost_per_attempt_cents` to `total_cost` inside the except branch on every failure, regardless of whether the callable actually consumed that cost:

```python
except Exception as exc:
    ...
    total_cost += estimated_cost_per_attempt_cents
    if total_cost >= self._budget_limit_cents:
        ...
```

If `execute_fn` fails before doing any real work (e.g., a pre-flight permission check raises immediately), the budget tracker still counts the full estimated cost. For functions that return `(output, actual_cost)` on success, there's no equivalent "actual cost on failure" signal. This means the budget pre-check `remaining < estimated_cost_per_attempt_cents` can terminate the loop one attempt too early when early failures are cheap but the estimate reflects a full execution.

The priority of diagnosis checks (blocker → decompose → reassign → transient) means a "timeout" error repeated 3 times will be classified as REPORT_BLOCKER not DECOMPOSE — the blocker check wins because it fires first. This is defensible (repeated identical timeouts *are* blockers) but could surprise if a caller expects DECOMPOSE for timeout patterns.

## Promotion engine's unused age guard

`PromotionCriteria` declares `min_age_hours: int = 24` with the docstring "Minimum age in hours before a fact is eligible for promotion (prevents premature promotion of new facts)." The `should_promote` method checks only `fact.access_count >= criteria.min_access_count` and cross-agent Jaccard similarity. It never inspects `fact.created_at` against `min_age_hours`. A fact stored and accessed three times in rapid succession (perhaps in a tight loop) qualifies for promotion immediately.

## Watchdog type safety and snapshot staleness

The `start_background_patrol` method accepts `agents_provider: Any`. A caller could pass a coroutine function (which would return a coroutine object, not a list) without any static analysis warning. Typing it as `Callable[[], list[AgentInfo]] | None` would surface these mismatches at lint time.

The patrol loop calls `agents_provider()` synchronously inside an async context. If the provider does I/O (e.g., queries a database), it would block the event loop. The current design assumes providers are cheap in-memory reads, which is fine for this sprint but worth noting if this evolves toward DB-backed agent state.

## Failure alchemy template specificity

The alchemist's value proposition depends on how specific the caller's `context` dict is:

```python
"rule_template": "Never run {action} without setting a timeout guard"
```

With `context = {"action": "deploy worker pod"}`, the antibody becomes actionable. With the default `"this operation"`, it becomes generic noise. The code does not validate or warn when context is sparse. Since the FailureAlchemist is designed for automated consumption, generating low-quality antibodies that enter the knowledge base silently is a quality concern.

## Context window capacity waste

The `get_context_window` allocation (L1: 1/4, L2: 1/2, L3: 1/4) is hardcoded. For agents that have no L1 summaries yet (new sessions), their L1 share is wasted — the returned list will be shorter than `limit`. The method doesn't redistribute unused capacity across layers, so a fresh agent requesting 20 items might get only 15 if L1 is empty.

## Test coverage gaps

Not tested: concurrent access to the PhaseMachine (two coroutines calling `approve_plan` on the same leader simultaneously); the `emit_learning_event` method on FailureAlchemist (only the event bus protocol is defined, no test exercises the publish path); `LayeredMemoryStore` behavior when `l2_max_facts` eviction triggers (L1 ring eviction is tested but not L2 capacity eviction); PromotionEngine behavior when `min_age_hours` is non-default (because the check doesn't exist).
