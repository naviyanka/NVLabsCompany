# Ecosystem Completion: SSRF guard, triggers, tool/skill catalogs, integration registry, semantic memory

Six features ported from the TypeScript Munder Difflin codebase to the Python Nexus backend, completing the planned import. The additions break into three clusters: network safety (SSRF guard), proactive agent automation (trigger types, classifier, context rules, history ledger, schema validator), and tooling/discovery (tool catalog, skills discovery, skills catalog, integration registry with Fernet-encrypted secrets, semantic memory via external CLI). Existing modules get surgical fixes: atomic index writes in `KnowledgeManager`, `enabled` filtering in webhook `set_endpoints`, legacy bare-POST routing, and a `rebuilt_text` field on `ReflectResult`.

Watch for: SSRF `safe_resolve` has no TOCTOU mitigation and uses blocking `socket.getaddrinfo` inside an async method (confirmed). The Fernet backend uses a hardcoded salt with no per-secret nonce differentiation at the KDF level (confirmed). The `SemanticMemoryManager.mine_agent` passes unsanitized `agent_id` into subprocess arguments (likely exploitable if agent IDs are user-controlled).

**Verdict**: APPROVED

## High-level view

The SSRF guard provides IP-range blocking and URL scheme enforcement, covering private ranges, IPv4-mapped IPv6 de-mapping, and cloud metadata IPs. The main gap is that `safe_resolve` is async in signature but synchronous in execution (blocking the event loop), and the check-then-use pattern leaves a DNS rebinding window that callers must close themselves.

The trigger system is a pure-data layer: frozen dataclasses for modes and context rules, a regex classifier, a capped history ledger, and a minimal JSON Schema validator. The classifier's "degrade to accept" stance on unknown schema keywords means callers relying on `pattern` or `additionalProperties` constraints will get silent pass-through.

The integration registry delegates all cryptography to a `SecretBackend` protocol with a Fernet implementation deriving keys via PBKDF2. Fail-closed when no key is configured. The in-memory ciphertext store means secrets are lost on restart — appropriate for this stage but worth noting for production planning.

Semantic memory wraps an external `mempalace` CLI binary with graceful degradation. The subprocess calls avoid `shell=True`, but agent IDs flow directly into argv without validation, creating an argument-injection surface if IDs are user-controlled.

## SSRF guard: blocking DNS and the rebinding gap

`safe_resolve` is declared `async` but calls `socket.getaddrinfo` synchronously. In a FastAPI/asyncio server, this blocks the event loop for the duration of the DNS lookup — typically milliseconds, but potentially seconds on a slow resolver or timeout. The fix is trivial: `await asyncio.get_event_loop().getaddrinfo(...)` or `run_in_executor`.

More fundamentally, `safe_resolve` returns a dict of addresses that the caller must trust will still be valid when they make the actual HTTP request. A malicious server can respond with a safe address for the validation query and an internal address for the subsequent connection query — classic DNS rebinding. The guard doesn't provide a way to pin the resolved address to the outgoing socket. This limitation should be documented in the docstring so callers know they need to connect to the validated IP directly rather than re-resolving via hostname.

The `is_safe_url` function permits `http://localhost:<any-port>`. In production, any service bound to loopback is reachable if an attacker controls the URL string — Elasticsearch on 9200, Redis on 6379, cloud metadata proxies on custom ports.

## Fernet secret backend: salt reuse and in-memory store

The PBKDF2 derivation uses a class-level constant salt (`b"nexus-integration-secrets"`) and 480,000 iterations. Since the salt is fixed, two deployments with the same `secret_key` produce byte-identical Fernet keys. The Fernet token itself contains a random IV so ciphertext is still non-deterministic, but the derived key is brute-forceable at the same cost regardless of per-secret isolation. Worth documenting for multi-tenant deployments.

The `_mining` flag in `SemanticMemoryManager` serializes `mine_all` calls but is not thread-safe (no lock). In a single-threaded asyncio context this holds, but sharing the manager across threads would allow concurrent entry.

## Semantic memory: subprocess argument handling

`mine_agent` constructs a command list:

```python
cmd = [bin_path, "mine", agent_dir, "--wing", agent_id, "--agent", agent_id]
```

Since `shell=False`, shell metacharacters are harmless. However, if `agent_id` starts with `--`, it could be interpreted as a flag by the `mempalace` binary's argument parser. A standard mitigation is to validate that `agent_id` matches `^[a-zA-Z0-9_-]+$` or to insert `--` before positional arguments. The risk depends on whether agent IDs are system-generated or user-supplied — the code doesn't enforce that constraint.

## Trigger classifier: silent pass-through on unknown schema keywords

The `validate_against_schema` function handles `type`, `required`, `properties`, and `enum` but silently accepts unknown keywords. Schemas using `pattern`, `minLength`, or `additionalProperties` will validate everything without error — callers need to be aware that this is a subset validator that degrades open, not closed.

## Test coverage gaps

337 new tests pass across 10 test files covering happy paths and edge cases comprehensively.

Not tested: `safe_resolve` behavior when `getaddrinfo` returns duplicate addresses across multiple address families (the dedup uses list membership, O(n²) but functionally fine). The `tool_catalog` tests don't exercise the dynamic engine entry generation path when `PROVIDER_PRESETS` is empty. The `ClosingTimeController` tick/timeout test doesn't verify that `on_concluded` is NOT called on timeout (only that the phase changes).
