# Evolution Intelligence: Statistical Rigor and LLM Integration

This change adds five modules to the Evolution subsystem that layer statistical analysis, A/B testing, LLM-driven improvement proposals, resource-isolated sandbox execution, and an LLM evolution advisor on top of the existing heuristic evolution engine. The approach is additive — no existing code was modified beyond `__init__.py` exports. The statistical layer implements Welch's t-test, linear regression, and confidence intervals from scratch using only stdlib `math` and `statistics`. The LLM modules follow the established `Callable[[str], Awaitable[str]]` pattern with fallback-first design, and the sandbox uses logical accumulators rather than OS-level enforcement.

Watch for: The confidence interval in `run_test` uses a z-score approximation instead of the t-distribution, which understates interval width at small sample sizes (confirmed). The `IsolatedSandbox.execute` only inspects resource metadata returned by the callable itself, meaning a misbehaving callable that doesn't report its costs passes through unchecked (confirmed). The `is_improvement` definition conflates statistical significance with practical significance in a compound boolean that may surprise callers (confirmed).

**Verdict**: APPROVED

## High-level view

The statistical module implements Welch's t-test via regularized incomplete beta function (Lentz continued fraction) and the Abramowitz-Stegun rational approximation for inverse normal CDF. The gap: `ABTestFramework.run_test` uses the normal approximation for its confidence interval while the hypothesis test uses the t-distribution, producing intervals that are inconsistent with the p-value at small sample sizes.

The A/B testing module layers experiment design, execution, and O'Brien-Fleming early stopping over the statistical analyzer. Post-hoc power estimation is included but cannot drive prospective decisions — callers should use `design_test` for that.

The LLM proposer and evolution advisor follow the same structural pattern as the existing `LLMTaskPlanner`: prompt templating, JSON parsing with field validation, and broad exception catch with heuristic fallback. Prompt injection surface exists via `json.dumps(context)` being interpolated directly into the prompt template; low risk since the LLM callable is internal, but worth hardening if the API surface expands.

The isolated sandbox is a logical resource tracker that trusts the code it's executing to self-report cost and memory. Only wall-clock duration is independently measured, and even that is post-hoc (checked after completion, not interrupted). This limits the sandbox to cooperative callables.

Test coverage is dense for the statistical and A/B testing modules but misses the memory limit breach path in the sandbox, direct validation of O'Brien-Fleming boundary values against reference tables, and prompt template formatting edge cases (context containing `{` or `}`).

<summary>Issues (5)</summary>

1. **CI width understated at small n** — `ABTestFramework.run_test` uses `_z_score_for_confidence` (normal quantile) instead of a t-quantile for the difference CI. At n < 30, this produces intervals that are too narrow. Use the t-distribution p-value machinery already in `StatisticalAnalyzer` to derive the critical value, or document the approximation.
2. **Sandbox trusts callable self-reporting** — `IsolatedSandbox.execute` only accumulates cost/memory from the callable's return dict. A callable that omits these keys or lies about them bypasses all limits except wall-clock duration. If this is intentional, document it; if not, add independent metering for at least duration-based abort (which is already there via `time.monotonic`) and consider making cost/memory required fields.
3. **Compound `is_improvement` semantics** — `StatisticalAnalyzer.is_significant_improvement` returns `is_improvement = True` only when all three conditions hold (mean2 > mean1 AND statistically significant AND practically significant). This is defensible but the name suggests it checks direction only. Callers expecting "did treatment beat control?" without the significance gate will misinterpret it.
4. **Prompt injection via context serialization** — `LLMImprovementProposer` and `LLMEvolutionAdvisor` interpolate `json.dumps(context)` directly into prompt templates. If context contains adversarial strings, they can inject instructions. Low risk since the LLM callable is internal, but worth noting for future exposure.
5. **No async support in sandbox execute** — `IsolatedSandbox.execute` calls `callable_fn(*args)` synchronously. The LLM integration modules are async throughout. If a proposal evaluation needs to call an async function (e.g., the LLM callable), it cannot be run in the sandbox without wrapping in `asyncio.run`, which would fail inside an already-running event loop.

## Confidence interval mismatch in run_test

In `ab_testing.py` line ~145, the confidence interval for the mean difference uses:

```python
z = self.analyzer._z_score_for_confidence(1.0 - alpha)
ci_lower = mean_diff - z * se_diff
ci_upper = mean_diff + z * se_diff
```

This is a z-based interval. The significance test in `compute_significance` correctly uses the t-distribution via `_t_distribution_two_tailed_p`. For the CI to be consistent with the hypothesis test, it should use the t-critical value at the Welch-Satterthwaite degrees of freedom. At n=10 per group, the t-critical value at 95% is ~2.10 vs z=1.96 — the CI is about 7% too narrow. A caller comparing the CI to zero to judge significance could reach a different conclusion than the p-value. [confirmed]

## Sandbox resource model is cooperative-only

`IsolatedSandbox.execute` tracks three resources: cost (from `result.get("cost_cents", 0)`), memory (from `result.get("memory_mb", 0)`), and duration (from `time.monotonic`). The first two depend entirely on the callable's cooperation:

```python
if isinstance(result, dict):
    cost_incurred = result.get("cost_cents", 0)
    memory_used = result.get("memory_mb", 0)
```

If the callable returns a non-dict, both accumulators stay at zero regardless of actual consumption. Duration is the only independently measured limit, and even that is post-hoc — a callable that blocks for longer than `max_duration_seconds` will complete before the check fires. [confirmed]

## The compound `is_improvement` gate

```python
"is_improvement": mean2 > mean1 and sig_result["is_significant"] and is_practically_significant,
```

This folds three conditions into one boolean. A caller asking "did treatment outperform control?" expects direction only. A caller asking "should we ship this?" expects the full gate. The field name suggests the former but implements the latter. The individual components are all available in the return dict for decomposition, but the name is misleading. [confirmed]

## Trend detection direction threshold

`detect_trend` uses a `normalized_slope` threshold of 0.1 to distinguish flat from trending:

```python
normalized_slope = abs(slope * (n - 1)) / data_range
if normalized_slope < 0.1:
    direction = "flat"
```

The normalization divides the total predicted change by the data range. A series with a consistent slope=1 over 10 points but a single spike creating a range of 1000 gets `normalized_slope = 0.009` and is classified "flat" despite a clear linear component. The R-squared is available for cross-checking, but the `direction` field alone is misleading for data with outliers. [likely]

## Async gap in sandbox

The sandbox's `execute` is synchronous. The LLM modules are all async. These don't compose directly — a caller wanting to evaluate an LLM-based proposal inside the sandbox would need to bridge the async gap, which fails inside an already-running event loop. A future `async_execute` method would close this. [confirmed]

## Test coverage gaps

Not tested: memory limit enforcement (no test triggers `ResourceLimitExceeded` for memory). The O'Brien-Fleming spending function lacks direct validation against known reference boundary values. Prompt templates aren't tested for formatting correctness with adversarial context (e.g., context containing `{` or `}` that could break `.format()`).
