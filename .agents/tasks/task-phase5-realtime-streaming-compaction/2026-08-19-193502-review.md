# Real-time streaming and session compaction (v2)

Phase 5 adds WebSocket connection management, SSE streaming with pub/sub, and session context compaction. The v1 issues — dead `_filtered_stream`, missing `__all__` fan-out, absent auth on both endpoints, undocumented dual registries, and unclosed sockets on disconnect — have all been addressed. The endpoints now require authentication (query param for WS, header for SSE), the event bus fans out to `__all__` subscribers, the WebSocketManager calls `websocket.close()` on disconnect, and `channels.py` carries a clear architecture note explaining the intentional registry separation.

Watch for: Auth gates the connection but events are not filtered by tenant — any authenticated client receives all published events regardless of company_id (confirmed). The `__all__` fan-out and auth enforcement both lack unit-test coverage (confirmed). The summarize strategy's extractive approach can truncate mid-sentence for content without early punctuation (confirmed, minor).

**Verdict**: NEEDS_CHANGES

## High-level view

Authentication now exists on both endpoints, but it functions as a gate rather than a scope. The SSE endpoint accepts `company_id` as a dependency but never passes it to `_event_generator`, so once connected, a client from company A receives events published for company B. The WebSocket endpoint validates `company_id` but the `WebSocketManager` has no concept of tenant — `broadcast()` hits every connection regardless of origin company. This is the remaining tenant isolation gap.

The `__all__` fan-out fix in `RealtimeEventBus.publish()` correctly delivers to catch-all subscribers while avoiding double-delivery when the topic is literally `"__all__"`. However, neither this behavior nor the auth enforcement on the two endpoints has test coverage, meaning a regression could re-introduce the v1 bugs silently.

Session compaction is clean and well-tested. The three strategies work correctly and the token counter's heuristic (4 chars/token) is adequate for context-window estimation without external dependencies.

## Tenant scoping gap in event delivery

The SSE route signature:

```python
async def stream_events(
    request: Request,
    company_id: CurrentCompanyId,
    ...
) -> StreamingResponse:
    ...
    return StreamingResponse(
        _event_generator(request, types_list, channel),
        ...
    )
```

`company_id` is validated and then discarded. The generator subscribes to topics without any tenant qualifier. The same pattern appears in the WS endpoint — `validated_company_id` is checked at connection time but never associated with the client in the manager. `WebSocketManager._connections` is a flat `dict[str, WebSocket]` with no tenant metadata; `broadcast()` fans to all entries.

This means a multi-tenant deployment where a producer calls `event_bus.publish("task_progress", event)` delivers that event to every authenticated SSE client, regardless of which company the task belongs to. The fix is either to namespace topics by company (e.g., `f"{company_id}:task_progress"`) or to attach `company_id` to the `RealtimeEvent` and filter in the generator.

## Missing test coverage for fixed v1 issues

The v1 review flagged five issues; all five were fixed in code. Two of the fixes — the `__all__` fan-out semantics and the auth requirements — represent correctness-critical behavior but have zero test assertions covering them:

- `RealtimeEventBus.publish()` now delivers to `__all__` subscribers, but `TestRealtimeEventBus` has no test case subscribing to `"__all__"` and verifying delivery when publishing to a specific topic.
- `websocket_endpoint` rejects connections without a valid `company_id` query param (returns 1008), and `stream_events` requires the `X-Company-Id` header, but neither test file exercises these rejection paths.
- The `websocket.close()` call in `disconnect()` is also untested (no mock asserts `close` was called).

These are the paths most likely to regress because they're invisible without explicit tests.
