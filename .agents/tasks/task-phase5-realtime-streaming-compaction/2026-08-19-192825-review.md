# Real-time streaming (WebSocket, SSE) and session context compaction

This change introduces three subsystems: a WebSocket connection manager with channel-based subscriptions (`src/nexus/realtime/`), an SSE streaming endpoint backed by an async pub/sub event bus, and a session context compaction module (`src/nexus/memory/compaction.py`) providing truncate/summarize/sliding-window strategies for bounding conversation histories. The entire addition is inert at runtime until a producer calls `event_bus.publish()` or `manager.broadcast()` — no domain events flow through these paths yet.

Watch for: The SSE `__all__` catch-all subscription never receives events because the event bus publishes only to explicit topics (confirmed). Both WebSocket and SSE endpoints lack authentication and tenant isolation, meaning any client can connect and receive any tenant's events once a producer is wired in (confirmed). A dead function (`_filtered_stream`) ships in the events route (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The ChannelRegistry is independent from the WebSocketManager's internal channel tracking, creating two parallel subscription registries that are never reconciled — a latent consistency problem once both are used by callers.

The SSE endpoint subscribes to a `"__all__"` topic when no filter is specified, but `RealtimeEventBus.publish(topic, event)` only delivers to subscribers of the exact topic passed. A client connecting without filters receives zero events regardless of what's published. This is a functional bug in the routing layer.

Neither the WebSocket nor the SSE endpoint uses `CurrentCompanyId` or any authentication dependency. The rest of the codebase scopes routes via `CurrentCompanyId`; these new endpoints skip that pattern entirely. Once a domain producer begins publishing, any unauthenticated client can subscribe and receive cross-tenant events.

Session compaction's summarize strategy is extractive-only (first sentence of each message, up to 100 chars), which compresses poorly when messages have important content beyond the first sentence. Downstream consumers should be aware that the summary may omit critical details.

<details>
<summary>Issues (5)</summary>

1. **`__all__` catch-all is dead** — `RealtimeEventBus.publish()` delivers only to the exact topic; subscribers on `"__all__"` never receive anything. Either publish should fan out to `"__all__"` subscribers, or the SSE endpoint should subscribe to all existing topics dynamically.
2. **No authentication on WS/SSE endpoints** — Both `/ws/{client_id}` and `/events/stream` lack `CurrentCompanyId` or any auth dependency, unlike every other route in the codebase. Add the standard dependency injection before a domain producer is wired in.
3. **Dual channel registries** — `WebSocketManager._channels` and `ChannelRegistry` track subscriptions independently. Either unify them or document that ChannelRegistry is intended for a different use case.
4. **Dead code `_filtered_stream`** — The function is defined in `events.py` but never called. Remove it.
5. **WebSocket disconnect does not close the socket** — `manager.disconnect(client_id)` only removes tracking state; it never calls `websocket.close()`. If the connection is still open server-side after an application-level decision to disconnect, the socket leaks until TCP timeout.

## Event bus routing gap

The SSE endpoint (`src/nexus/api/routes/events.py`, line 69) subscribes to `"__all__"` when no `event_types` filter is provided:

```python
topics = event_types if event_types else ["__all__"]
for topic in topics:
    event_bus.subscribe(topic, queue)
```

`RealtimeEventBus.publish(topic, event)` only delivers to queues registered under the passed `topic` string. There is no fan-out to a wildcard/catch-all bucket. The default unfiltered SSE client receives nothing. The fix is either to have `publish` also deliver to `"__all__"` subscribers, or to have the endpoint subscribe to every topic dynamically (harder to maintain). Confidence: **confirmed** — verified by tracing `publish()` in `event_bus.py` line 76.

## Authentication and tenant isolation gap

Every domain route in this codebase uses `CurrentCompanyId` from `nexus.api.deps` for tenant scoping. The new routes:

- `GET /events/stream` — no auth, no company scoping
- `WS /ws/{client_id}` — no auth, client_id is caller-supplied with no validation

The WebSocketManager is a module-level singleton shared across all connections. Once a producer begins broadcasting domain events (agent status changes, task progress), every connected client receives them regardless of which company the event belongs to. The event bus has no concept of tenant filtering. This needs the standard `CurrentCompanyId` dependency (or a WebSocket-specific auth handshake via query token) before real events flow through. Confidence: **confirmed**.

## Dual subscription registries

`WebSocketManager` maintains `self._channels: dict[str, set[str]]` mapping channel names to subscriber client_ids. Separately, `ChannelRegistry` maintains `self._channels: dict[str, RealtimeChannel]` with its own subscriber sets. The WS route (`ws.py`) uses only `manager.subscribe_channel()`; it never interacts with `ChannelRegistry`.

There is no synchronization: creating a channel in the registry does not register it in the manager, and subscribing via the manager does not register in the registry. A future caller using `ChannelRegistry` to check subscribers will get stale data. Confidence: **confirmed** — both classes maintain independent state with no cross-reference.

## WebSocket disconnect lifecycle

`WebSocketManager.disconnect(client_id)` removes the client from `_connections` and from all channel subscriber sets, but does not call `websocket.close()`. In the normal `WebSocketDisconnect` exception path, the client has already disconnected. But if application code calls `manager.disconnect(client_id)` proactively (e.g., on auth revocation or eviction), the underlying TCP connection remains open until the client or OS closes it. The `send_personal` and `broadcast` methods catch send failures and call `disconnect`, creating a removal-without-close pattern. Confidence: **likely** — the public API invites proactive use without closure.

## Dead code in events route

`_filtered_stream` (lines 27–43 of `events.py`) accepts an `EventStream` and filter params, yields from `stream.stream()` without applying any filter, and is never referenced anywhere. It was superseded by `_event_generator`. Confidence: **confirmed**.

## Test coverage gaps

Not tested: the actual FastAPI endpoint integration (no `TestClient` is used for the WS or SSE routes), the interaction between `events.py` route and `RealtimeEventBus` at the HTTP level (which would surface the `__all__` topic gap), and the keepalive timeout path in `_event_generator`.
