# Phase 7: Tree-of-Thought reasoning, OKR management, archetype templates, and LLM provider adapters (v2)

This is a v2 review following fixes to all 6 issues raised in v1. The Google Gemini API key now passes via `x-goog-api-key` header, conversation history is capped at 50 messages in all three adapters, the OKR module-level state has a clarifying comment acknowledging the single-worker constraint, the ToT fallback annotates subtasks with `metadata["fallback"]=True` and `metadata["reason"]`, the httpx client is created outside the retry loop for connection reuse, and cost tracking uses `round()` instead of `int()`. Watch for: the Azure adapter's history cap discards the system prompt once the conversation exceeds 50 messages (confirmed).

**Verdict**: APPROVED

## High-level view

All six v1 issues are resolved. One new minor concern: the Azure adapter stores the system prompt as `history[0]` and truncates with `history[-50:]`, which drops the system prompt from long conversations. The Bedrock and Gemini adapters are unaffected because they pass system prompts separately in the request body. This is non-blocking — 50 messages is generous for most agent sessions, and the behavior degrades gracefully (the model loses persona guidance rather than erroring).

## Azure system prompt dropped by history window

The Azure adapter initializes the system prompt as the first message in conversation history:

```python
self._conversation_history[session.session_id] = [
    {"role": "system", "content": system_prompt}
]
```

After each exchange, the cap applies:

```python
if len(history) > MAX_HISTORY_MESSAGES:
    history = history[-MAX_HISTORY_MESSAGES:]
```

Once a session accumulates more than 50 messages (25 round trips), the slice drops the system message at index 0. The model then operates without persona instructions for the remainder of the session. The Bedrock and Gemini adapters avoid this by storing the system prompt in `session.metadata` and injecting it into the request body independently of the message array.

Fix: after slicing, re-insert the system message at position 0, or switch to the metadata approach used by the other two adapters.
