# Phase 7: Tree-of-Thought reasoning, OKR management, archetype templates, and LLM provider adapters

This change adds four subsystems to the Nexus platform: a Tree-of-Thought (ToT) reasoning engine for multi-step task decomposition, an OKR management system with REST API, a 20-archetype agent template library, and three new LLM provider adapters (Azure OpenAI, AWS Bedrock, Google Gemini). The implementation is in-memory throughout, follows existing patterns (BaseAdapter subclassing, dataclasses, FastAPI routers), and brings 97 new test methods. Watch for: the Google Gemini adapter passes the API key as a URL query parameter (confirmed), the OKR API uses a module-level mutable dict as its persistence layer meaning state leaks across requests in a multi-worker deployment (confirmed), and conversation history in all three adapters grows without bound (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The ToT reasoning engine wraps an LLM callable in a beam-search loop over a tree of thought nodes, then converts the best path into SubTask objects. The fallback to TaskPlanner's `_default_decomposition` on any exception makes it resilient but also means malformed LLM output silently degrades to single-step planning with no signal to the caller.

The OKR subsystem stores objectives and key results in an in-memory dict scoped to a module-level `_managers` cache keyed by company UUID. Risk detection is time-fraction-based but the time fraction is caller-supplied, not derived from the objective's `time_frame` field, so the "detect at risk" heuristic is decoupled from the data it claims to interpret.

The three LLM adapters share a consistent pattern: validate config, construct provider-specific HTTP requests with retry on 429, track conversation history. The Google adapter leaks the API key into the request URL. All adapters create a fresh `httpx.AsyncClient` per retry attempt instead of reusing a connection pool, and none cap conversation history growth.

<details>
<summary>Issues (6)</summary>

1. **Gemini API key in URL** — The Google adapter passes `?key={api_key}` as a query parameter, which will appear in access logs, proxy logs, and error traces. Pass it as a header (`x-goog-api-key`) or move to OAuth.
2. **Unbounded conversation history** — All three adapters append to `_conversation_history` on every call with no truncation or eviction. Long-lived sessions will accumulate unbounded memory and eventually hit the provider's context window limit with no graceful handling.
3. **OKR manager module-level state** — `_managers` in `okr.py` routes is a module-level dict. In multi-worker deployments (uvicorn --workers > 1), each worker gets independent state. In a single-worker process, it leaks across test runs and concurrent requests without any locking.
4. **Silent fallback in ToTPlanner** — `decompose_task` catches all exceptions and returns a single-subtask fallback. The caller receives no indication that tree exploration failed, making it impossible to distinguish "task is genuinely simple" from "LLM was unreachable."
5. **httpx.AsyncClient per retry** — Each retry attempt creates and tears down a new `AsyncClient`, paying TLS handshake cost every time. This defeats connection pooling and adds latency to retry paths.
6. **Cost truncation to int** — All adapters cast cost to `int(...)` cents, which rounds sub-cent costs to zero for cheap models (Gemini Flash at 0.0075¢/1K tokens will report 0 cost for most calls).

## Gemini API key exposure in URL

In `google_adapter.py`, the request URL is constructed as:

```python
url = (
    f"{self._api_base}/models/{model}:generateContent"
    f"?key={api_key}"
)
```

HTTP proxies, CDN edge logs, and application error reporters routinely capture full URLs. The Gemini API accepts the key via an `x-goog-api-key` header, which keeps it out of access logs. The Azure adapter correctly uses a header (`api-key`), so this inconsistency is specific to the Google path.

## Unbounded conversation history in all adapters

All three adapters append user and assistant messages to `self._conversation_history[session.session_id]` on every `execute_task` call with no truncation, sliding window, or summarization. For long-running agent sessions this means memory consumption grows linearly with calls, and eventually the full history will exceed the provider's max context window. The adapters send the entire history as `messages`, so the provider will return a 400/context-length error, which surfaces as a generic API error with no recovery path.

A truncation strategy (token-budget window or message-count cap) would prevent both the memory leak and the silent 400 failure mode.

## OKR module-level state and concurrency

The OKR routes use a module-global `_managers: dict[uuid.UUID, OKRManager] = {}`. In production with multiple uvicorn workers, each worker has independent OKR state. The constructor accepts a `_db` parameter that is never used, so the "optional database persistence" path doesn't exist. Within a single worker, `update_progress` performs a linear scan across all objectives to find a key result by ID — fragile if the dataset grows, and the scan has no index.

## Silent fallback in ToTPlanner

```python
except Exception:
    return self._fallback_planner._default_decomposition(
        task_id, description, context
    )
```

Any failure — network timeout, JSON parse error, LLM returning nonsense scores — silently produces a single subtask. The caller has no way to know tree exploration was attempted and failed. Adding a flag in the returned subtask metadata (e.g., `"fallback": True`) would let upstream code decide whether to retry or alert.

## httpx.AsyncClient instantiation per attempt

All three adapters create a new `httpx.AsyncClient` inside the retry loop:

```python
for attempt in range(MAX_RETRIES):
    async with httpx.AsyncClient(timeout=120.0) as client:
        response = await client.post(...)
```

Each iteration negotiates a fresh TCP connection and TLS handshake. Moving the client outside the loop (or to session-level) would reuse the connection across retries.

## Cost tracking rounds to zero for cheap models

```python
cost_cents = int(
    (input_tokens / 1000 * pricing[0])
    + (output_tokens / 1000 * pricing[1])
)
```

For Gemini Flash (0.0075¢ input, 0.03¢ output), a typical 500-token call costs ~0.02¢, which `int(...)` truncates to 0. Over many calls the accumulated reported cost is 0, masking actual spend. Using `round()` or tracking in sub-cent units (microcents) would preserve accuracy.

## Test coverage gaps

Not tested: conversation history overflow behavior, concurrent access to OKRManager, Bedrock SigV4 signature correctness against known test vectors, Google adapter behavior when `candidates` list is empty (the code handles it but no test covers the branch), `_do_terminate` clearing history in the presence of concurrent calls.
