# Sprint 5: Operational Backbone for Multi-Agent Coordination

This change introduces five foundational subsystems for managing autonomous agents at scale: per-model cost estimation, CLI provider presets, an advanced multi-signal circuit breaker, portable hire manifests with security validation, and a file-based hive protocol for inter-agent messaging. Together they form the operational backbone—cost awareness, runaway prevention, agent provisioning, and coordination—needed before agents can run unsupervised. The implementation is well-tested (195 new tests) and properly isolated from the existing 1,230-test baseline.

Watch for: the circuit breaker's `_tool_key` method performs redundant serialization passes and loses `sort_keys`, causing key-order-dependent deduplication that can miss loops (confirmed); the hive protocol has no message authentication, meaning any process with filesystem access can inject messages into an agent's inbox (confirmed); `price_for()` keyword matching is fragile—the `"o1" in m` check would false-positive on model names like "proto1-large" (likely); the hire manifest's `SAFE_FLAG_NAMES` allowlist is very small (4 flags), which blocks legitimate provider-specific flags (confirmed); and the hive router silently drops messages to unknown recipients with no error log (confirmed).

**Verdict**: APPROVED

## High-level view

The cost tracking module is a stateless lookup table with keyword-based model resolution, serving only the offline transcript reconciler. The keyword matching order matters: `gpt-4o-mini` must be checked before `gpt-4o`, and it is, but `o1` matching is loose enough to false-positive on model names containing that substring anywhere.

The circuit breaker implements a four-level escalation ladder evaluated per-tick across six trip conditions. It owns policy only—no side effects—which makes it testable and composable. The compaction-awareness exemption prevents false trips during memory compaction. The `_tool_key` implementation has a redundant triple-serialization path and loses key ordering, which can cause missed loop detection.

Hire manifests define a security-first portable agent template format. The command-flag allowlist is default-deny (only 4 flags pass), the model regex rejects shell metacharacters, and the provider field validates against a known set excluding `custom`. The tension between this strict allowlist and the provider presets' own flags (which include permission-escalation flags like `--yolo`) needs documentation.

The hive protocol implements FIPA-lite messaging over the filesystem with a HOP_CAP of 12 to prevent livelock. The design assumes a single-machine trust boundary with no message signing or sender verification—acceptable for the current single-user prototype, but a prerequisite for multi-host deployment.

## Circuit breaker: triple serialization in `_tool_key`

The `_tool_key` method builds a deduplication key from the tool name and input. It performs three serialization attempts in sequence:

```python
inp_str = json.dumps(tool_input, default=lambda v: str(v), sort_keys=True)
inp_str = json.dumps(tool_input, default=lambda v: str(v)[:250] if len(str(v)) > 250 else str(v))
inp_str = self._truncated_json(tool_input)
```

The first two results are immediately overwritten—dead code that runs on every tool call. More critically, `sort_keys=True` from the first call is lost because `_truncated_json` doesn't sort keys. This means key order affects deduplication: `{"a":1,"b":2}` and `{"b":2,"a":1}` produce different keys for the same logical input. An agent calling the same tool with the same arguments but different dict ordering would evade loop detection. The fix: replace all three lines with a single `_truncated_json` call that sorts keys.

## Hive protocol: filesystem trust boundary

The `HiveRouter.route()` method reads any `.json` file from an agent's outbox and trusts the `from_agent` field inside it. An attacker (or a misbehaving agent) with write access to another agent's outbox directory can:

1. Forge messages appearing to come from any agent
2. Send messages to "god" or "human" to escalate privilege
3. Broadcast fake instructions to the entire hive

This is acceptable for the current prototype where all agents run as the same Unix user. Before multi-host deployment, messages need at minimum an HMAC over (id, from_agent, to_agent, body) with a per-agent secret. The design should document the single-machine trust assumption explicitly.

## Price resolution: keyword ordering and false positives

The `price_for()` function checks model families by substring containment. The `"o1" in m` and `"o3" in m` checks are very broad—they would match any model ID containing those substrings anywhere (e.g., "proto1-large", "apollo1"). Current model naming conventions make false positives unlikely today, but as the model zoo grows this becomes fragile. A more robust approach: `re.search(r'\bo[13]\b', m)` or prefix-anchored checks.

## Hire manifest flag allowlist vs. provider preset flags

The manifest's 4-flag allowlist (`--model`, `--max-turns`, `--output-format`, `--verbose`) cannot express the provider presets' `auto_mode_flag` values (`--permission-mode bypassPermissions`, `--dangerously-bypass-approvals-and-sandbox`, `--yolo`, `--approve`). Manifests can't override auto-mode behavior per-role—the preset's `auto_mode_flag` is always used as-is. This means manifests also can't de-escalate permissions. The design intent (tuning parameters only, never permission flags) should be documented in the module docstring.

## Hive router: silent message loss for unknown recipients

When `to_agent` references a non-existent agent, `_resolve_recipients` returns `[]`. The router moves the message to `.sent` and logs `message_delivered` with `"recipients": []`—indistinguishable from a successful delivery with no recipients. A dedicated `delivery_failed_unknown_recipient` log event would make failed deliveries visible to debugging without changing routing semantics.

## Test coverage gaps

Not tested:

- Circuit breaker: the key-ordering issue in `_tool_key` (same logical input, different dict key order)
- Hive router: race conditions when multiple routers drain the same outbox simultaneously
- Hire manifest: round-trip serialization stability (import → export → re-import)
- Pricing: the `cache_write_per_m` multiplication path with a non-zero value (all OpenAI/Gemini constants have `cache_write_per_m=0`; only Anthropic models exercise this)
