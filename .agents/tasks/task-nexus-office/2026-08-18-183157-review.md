# 2D Virtual Office visualization for the NEXUS dashboard (v2)

A full-page interactive office floor plan rendering agents as avatars in department rooms, with pan/zoom canvas, delegation flow arrows, meeting rooms, activity ticker, and mobile list fallback. Fourteen new files implement the spatial layout, avatar rendering, SVG delegation overlays, and office controls; two existing files receive minimal routing additions. This second-pass review confirms all five issues from the first pass have been resolved and evaluates the fixes themselves.

Watch for: The `useAgentMovement` hook lives inside a component file (`AgentMovement.tsx`) that also exports a no-op component — importing a hook from a component module is unconventional and could confuse tooling or future developers expecting hooks to live in `hooks/` (possible). Night mode remains cosmetically incomplete with bright overlay panels against a dark canvas, though the spec calls this cosmetic and non-blocking.

**Verdict**: APPROVED

## High-level view

The five issues from the first review are all addressed. `useOffice` now delegates to `useAgentMovement` as the single source of position logic, the unreachable `paused`/`terminated` status color entries are removed, the wheel listener is attached imperatively with `{ passive: false }`, the meetings heuristic threshold is raised to 3 with a documenting comment explaining its fabricated nature, and `Office.tsx` consumes tasks from the hook instead of fetching independently.

The hook colocation in `AgentMovement.tsx` rather than in `hooks/` is the only remaining structural oddity — it violates the project's convention of placing hooks in `src/hooks/` and leaves a dead no-op component export in place.

<details>
<summary>Issues (2)</summary>

1. **Hook exported from component file** — `useAgentMovement` is defined in `components/office/AgentMovement.tsx` alongside a no-op component. The project convention places hooks in `src/hooks/`. Moving the hook to `hooks/useAgentMovement.ts` (or co-exporting from `hooks/useOffice.ts` since it's only consumed there) would align with the codebase pattern. Non-blocking.
2. **Night mode panel contrast** — Overlay panels (`StatusPanel`, `OfficeControls`, `ActivityTicker`) retain `bg-white/95` styling regardless of night mode, creating bright panels against the dark canvas. Cosmetic per spec, but worth a follow-up pass if night mode ships to users.

## Hook location convention

The project consistently places custom hooks in `src/hooks/` — `useApi.ts`, `usePolling.ts`, `useAgents.ts`, etc. The `useAgentMovement` hook is the sole exception, living in `src/components/office/AgentMovement.tsx`. The same file also exports a `function AgentMovement(_props) { return null; }` component that serves no purpose now that the hook is consumed directly by `useOffice`.

A developer looking for hooks in `hooks/` won't find it, and a developer scanning `components/` may not expect a hook export. Since `useAgentMovement` is only consumed by `useOffice`, it could be either inlined into that file or moved to `hooks/useAgentMovement.ts` without the dead component wrapper.
