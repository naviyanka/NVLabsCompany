# 3D Isometric Office Floor Plan via React Three Fiber

The Office page was gutted from a 2D SVG-based floor plan (with live API data via `useOffice()` hook) and rebuilt as a fully static Three.js scene using React Three Fiber. Fifteen new components render 9 named zones on an isometric grid, animated agent characters with status-based coloring, a glass-walled manager cabin, particle-based delegation flows, envelope-based report animations, and a click-to-inspect detail sidebar. The change replaces real API integration with hardcoded mock data (12 agents + 1 manager) and removes the mobile-responsive list view entirely.

Watch for: The previous Office page consumed live agent/task data from the API; this rebuild drops that integration entirely, locking the page into static demo data with no path back (confirmed). The old mobile-first responsive design (list view toggle, compact stats) was removed with no 3D fallback for small screens (confirmed). The bundle gains ~1.7MB from Three.js with no code-splitting or lazy loading applied (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The architectural decision is a full replacement rather than an incremental upgrade — the old page's hook-based data fetching, task correlation, navigation to agent detail routes, and mobile layout were all removed. The new page is a self-contained 3D demo driven entirely by a static config object. This means the page is no longer connected to the application's data layer, and the `MockAgent3D` type shares no shape with the existing `Agent` type, so reconnecting will require a mapping layer.

Animations are frame-driven (`useFrame`) with per-agent hash-based time offsets to desynchronize particle and envelope cycles. This creates a continuously-rendering canvas — roughly 40+ ref mutations per frame across agents, desks, particles, and envelopes — with no suspension when the tab is inactive or the scene is idle.

The removal of all responsive/mobile support is a significant regression: absolute-positioned overlays, `w-44` card strips, and WebGL touch conflicts make the page unusable on small screens. The old page's `MobileListView` and touch-friendly targets are gone with no replacement.

<summary>Details</summary>

## Static mock data replaces live API integration

The previous Office page imported `useOffice()` which fetched agents, tasks, computed stats, and correlated active tasks to agents via a `taskMap`. It also used `useNavigate()` to deep-link into `/agents/:id`. The new page imports nothing from the API layer. All 13 agents are defined as a literal array in `office3dLayout.ts` with hardcoded CPU/memory/task values and a fixed sparkline array of 8 numbers.

There's no adapter layer, no prop-passing of dynamic data into the scene, no interface that the API could plug back into. `StatsBar` and `AgentsAtGlance` both independently import and spread `[...mockAgents3D, managerAgent]` to derive counts — if the data source becomes dynamic, these direct imports will need to become props or context consumers. The sidebar's "View Full Profile" button doesn't navigate anywhere (previously this was `navigate('/agents/${agent.id}')`), and the quick actions section renders three buttons with no `onClick` handlers.

## Continuous rendering and performance

Every component that uses `useFrame` runs on every animation frame: `AgentCharacter` (12 instances), `Desk` (19 desks with `screenRef` animation), `DelegationAnimation` (6 working agents × particle + trail), `ReportAnimation` (2 review agents × envelope), and `ManagerCabin`. React Three Fiber's render loop never suspends because at least one object's material opacity is always animating.

On integrated GPUs or older devices, a permanently-spinning WebGL context will heat the device and drain battery. The standard mitigation is R3F's `frameloop="demand"` with manual `invalidate()` calls, or pausing via `document.hidden` detection. Neither is implemented. If the agent count grows beyond the current 13, the per-frame cost scales linearly with no upper bound.

## Mobile and responsive regression

The new layout uses absolute positioning for overlays (`StatsBar` at top, `AgentsAtGlance` at bottom, `AgentDetailSidebar` at right). `AgentsAtGlance` renders 13 cards at `w-44` each in a horizontal scroll — on a 375px phone screen, the stats bar text will overflow, the bottom cards will be cramped, and the 3D canvas interaction (drag, pinch) will conflict with page scroll.

`CameraControls` maps `touches.ONE` to orbit and `touches.TWO` to zoom, but the overlay divs sit on top of the canvas with `z-10` and `pointer-events-auto`. Touch targets on mobile will be intercepted by overlays before reaching the canvas, making the 3D scene effectively non-interactive on phones.

## Fragile event type assertion

`AgentCharacter` and `ManagerCabin` both cast R3F's click event with `(e as unknown as { stopPropagation: () => void }).stopPropagation()`. R3F's event system does provide `stopPropagation`, but the double-cast through `unknown` bypasses all type checking. If R3F changes its event shape in a future version, this will silently stop preventing propagation without a compile error. A safer pattern is to type the handler parameter as `ThreeEvent<MouseEvent>` from `@react-three/fiber`.

## Stale memos if data becomes dynamic

Both `DelegationAnimation` and `ReportAnimation` use `useMemo(() => mockAgents3D.filter(...), [])` with an empty dependency array. Since the data is currently a static import this works correctly, but the pattern will silently break if agent data is ever passed as props or pulled from context — the filtered lists will never update. Worth noting as a latent footgun for whoever reconnects live data.
