## High-level view

The webhook queue's lifecycle is now correct: `dequeue()` moves items to `_in_flight`, `ack()` and `nack()` operate on that dict, and in-flight state is persisted across restarts. The gap is ungraceful crashes or consumer abandonment — items in `_in_flight` have no timeout-based recovery back to `_pending`.

The reflector's `_extract_durable_facts` now participates in the condensation pipeline through `_heuristic_fallback`. The `ThreadPoolExecutor` is cached on the instance rather than created per call, but has no explicit shutdown — a minor resource leak for instances that get discarded without cleanup.

## In-flight stall recovery

Once an item enters `_in_flight` via `dequeue()`, nothing returns it to `_pending` unless `nack()` is explicitly called:

```python
def dequeue(self) -> WebhookDelivery | None:
    now = datetime.now(UTC)
    for i, delivery in enumerate(self._pending):
        if delivery.next_retry_at is None or delivery.next_retry_at <= now:
            self._pending.pop(i)
            delivery.status = "in_flight"
            self._in_flight[delivery.id] = delivery
            self._save()
            return delivery
    return None
```

A consumer that crashes, hangs, or silently drops the item leaves it stranded — not in pending, not in dead letters, stuck in in-flight limbo. A `recover_stale(timeout: timedelta)` method scanning `_in_flight` for items past a threshold and returning them to `_pending` (incrementing retry_count) would close this gap. Alternatively, `dequeue()` could perform this check as a preamble.

## Executor lifecycle on MemoryReflector

The cached executor persists for the lifetime of the `MemoryReflector` instance:

```python
if self._executor is None:
    self._executor = concurrent.futures.ThreadPoolExecutor(1)
future = self._executor.submit(
    asyncio.run,
    self._summarize_evicted(condensed_text, evicted, pinned),
)
```

Each abandoned instance holds a thread until GC collects it and CPython's finalizer runs `shutdown(wait=False)`. In test suites creating many reflector instances, this accumulates idle threads and file descriptors. A `def close(self)` calling `self._executor.shutdown(wait=False)` would allow explicit cleanup where callers want it.
