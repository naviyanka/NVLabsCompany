# Operational maturity: LLM reflector, webhook queue, approvals persistence, worktree edge cases

Four features added to harden the Nexus platform for production: an LLM-powered memory condensation path for the reflector, a file-backed webhook delivery queue with retry and dead-lettering, persistence and audit history for the approval engine, and edge-case tests for the git worktree manager. All four maintain backward compatibility — new parameters are optional with `None` defaults. Atomic file writes follow the established `tempfile + os.replace` pattern. 58 new tests across 4 files; full suite at 2054 tests.

Watch for: The webhook queue's dequeue/ack/nack lifecycle is broken — `dequeue()` removes from `_pending`, so subsequent `ack()` or `nack()` silently fails to find the item (confirmed). `_extract_durable_facts` is implemented and tested but never called in any production path (confirmed). The `make_summarizer()` ThreadPoolExecutor bridge spawns a thread per condensation call with no pool reuse (likely).

**Verdict**: NEEDS_CHANGES

## High-level view

The webhook queue has a fundamental lifecycle bug: `dequeue()` removes items from `_pending`, but `ack()` and `nack()` search `_pending` to operate on items. In a real dispatch loop (enqueue → dequeue → attempt delivery → ack/nack), the delivery will never be found after dequeue. The tests never exercise this sequence — they call `ack`/`nack` on items still in `_pending` — so the bug is invisible to the test suite.

The reflector's LLM integration has sound structure — prompt construction, JSON parsing with heuristic fallback, and the verify-don't-trust gate protecting against bad LLM output. However, `_extract_durable_facts` — the method that identifies decision lines, file paths, SHAs, and numbers — is never wired into `_summarize_evicted` or `make_summarizer`. It's dead code unless callers invoke it manually, which undermines the "durable fact hoisting" feature.

The approvals persistence serializes the full `_approvals` dict on every mutation with no pruning or archival. For a long-running system this file grows without bound, progressively slowing `_load()` and `_save()`.

## Webhook queue: dequeue removes before ack/nack can operate

The delivery lifecycle has three intended phases: enqueue (producer adds work), dequeue (consumer takes work), and ack/nack (consumer reports outcome). But `dequeue()` pops the item from `_pending`:

```python
def dequeue(self) -> WebhookDelivery | None:
    now = datetime.now(UTC)
    for i, delivery in enumerate(self._pending):
        if delivery.next_retry_at is None or delivery.next_retry_at <= now:
            self._pending.pop(i)
            self._save()
            return delivery
    return None
```

After this, `ack()` and `nack()` both iterate `self._pending` looking for the delivery by ID — they'll never find it.

The test suite never catches this because every test that calls `nack()` or `ack()` does so on items that were enqueued but never dequeued:

```python
def test_nack_increments_retry(self, tmp_path):
    queue = WebhookDeliveryQueue(persist_path=tmp_path / "queue.json")
    queue.enqueue(_make_delivery(id="d1"))
    queue.nack("d1", "connection timeout")  # item still in _pending
```

The fix is an `_in_flight: dict[str, WebhookDelivery]` that `dequeue()` moves items into, with `ack()` and `nack()` operating on `_in_flight`. Items moved back to `_pending` on nack (with updated retry), removed on ack, and the dict persisted alongside `_pending` and `_dead_letters`.

## Reflector: _extract_durable_facts disconnected from pipeline

`_extract_durable_facts` scans evicted sections for lines containing decisions, file paths, commit SHAs, and critical numbers. The spec describes this as feeding hoist candidates into the condensation pipeline. But `_summarize_evicted` never calls it:

- In the LLM path, the prompt asks the LLM to return `hoist_lines`, but `_extract_durable_facts` isn't used as a pre-filter or fallback when the LLM returns empty hoist lines.
- In the heuristic fallback, `_heuristic_fallback` always returns an empty hoist list `[]`, never consulting `_extract_durable_facts`.

The natural integration point is the heuristic fallback: when no LLM is available, `_extract_durable_facts` could provide the hoist lines that the heuristic currently leaves empty.

## make_summarizer ThreadPoolExecutor lifecycle

The sync-to-async bridge in `make_summarizer` creates a `ThreadPoolExecutor(1)` on every call:

```python
if loop and loop.is_running():
    import concurrent.futures
    with concurrent.futures.ThreadPoolExecutor(1) as pool:
        future = pool.submit(asyncio.run, self._summarize_evicted(...))
        return future.result()
```

The `with` block shuts down the executor (joining the thread) after each call. In a batch scenario where multiple agents' memories are condensed in sequence, this creates N threads sequentially — each spawned and joined. A single cached executor on the `MemoryReflector` instance would eliminate the thread churn.

## Test coverage gaps

Not tested: the dequeue→ack and dequeue→nack real-world flow (the critical lifecycle bug), `_extract_durable_facts` integration with the condensation pipeline (because it's not wired in), and approvals persistence file growth under high volume.
