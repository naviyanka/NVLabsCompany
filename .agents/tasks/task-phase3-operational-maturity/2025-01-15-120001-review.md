# Phase 3 Operational Maturity — v2 review after fixes

Seven operational-maturity features in one batch: cost alerting with deduplication, secret rotation lifecycle with REST API, API versioning middleware and deprecated-route support, audit log export with retention policies, codebase-wide `datetime.utcnow()` elimination, startup config validation, and graceful shutdown hooks. All six issues from the v1 review have been addressed: ControlRegistry now persists via the runtime singleton, telemetry reset was removed with a clear comment explaining why, cost alerts deduplicate by severity, the misleading Redis log was removed, the deprecated route signature is documented as intentional, and the rotation trigger endpoint carries a WARNING docstring about TLS/auth requirements.

Watch for: The `deprecated_wrapper` docstring claims compatibility with "any standard FastAPI signature" but the implementation still passes only `(request: Request)` to the original endpoint, contradicting the claim (confirmed). Cost alerting callbacks have no exception isolation — a raising callback aborts remaining callbacks and the rest of the check loop (confirmed). The `AuditExporter` directly mutates `AuditLogger._entries` during retention, coupling the exporter to the logger's internal storage representation (confirmed).

**Verdict**: APPROVED

## High-level view

The `deprecated_wrapper` in `VersionedRouter` enforces a `Request`-only signature on wrapped endpoints. The docstring claims it supports "any standard FastAPI signature," but the implementation calls `await original_endpoint(request)` directly, bypassing FastAPI's dependency injector. This is a documentation-vs-code mismatch rather than a blocking bug, since the deprecated route mechanism currently works for its intended use case (simple handlers).

Cost alerting deduplication tracks a `_last_severity` map per scope and suppresses re-fires unless severity escalates or the scope drops below threshold and re-crosses. However, callback invocation has no exception isolation: if a callback raises, the remaining callbacks for that alert and all subsequent scope checks are abandoned. The deduplication logic sets `_last_severity` before invoking callbacks, so a failed delivery still marks the alert as "sent" — the scope won't re-fire on the next poll.

Both `CostAlertService` and `AuditExporter` reach directly into private attributes of their collaborators (`BudgetEnforcer._budgets/_spent/_scope_agent`, `AuditLogger._entries`). The `AuditExporter` additionally reassigns the list reference during retention, creating a narrow race with concurrent `log_event()` calls that append to the old reference.

## Deprecated route wrapper vs docstring

The `add_deprecated_route` method in `src/nexus/api/versioning.py` line 125 defines:

```python
async def deprecated_wrapper(request: Request) -> Response:
    result = await original_endpoint(request)
```

FastAPI resolves dependencies by inspecting the handler's signature. Because `deprecated_wrapper` declares only `request: Request`, FastAPI will inject the raw request — path parameters, query parameters, and `Depends(...)` annotations on the original endpoint are never resolved. The docstring on line 105 says "The endpoint can use any standard FastAPI signature (path params, query params, dependency injection)" which is inaccurate. The next developer who reads the docstring and tries to deprecate a handler with `Depends(get_db)` will get a confusing runtime error.

## Cost alert callback failure propagation

In `src/nexus/governance/cost_alerting.py` lines 216–217:

```python
for callback in self._callbacks:
    callback(alert)
```

If the first registered callback raises (network timeout to a webhook, serialization error, permission issue), the second callback never fires, and the `for (scope_type, scope_id), threshold in self._thresholds.items()` loop terminates with an unhandled exception. In a periodic polling deployment, one transient callback failure suppresses all alerting until the next successful poll — and the deduplication logic may then suppress the alert on the next pass because `_last_severity` was already set before the exception.

The fix:

```python
for callback in self._callbacks:
    try:
        callback(alert)
    except Exception:
        logger.warning("Alert callback failed", exc_info=True)
```

## AuditExporter's coupling to AuditLogger internals

`apply_retention()` reassigns the logger's internal list:

```python
self._logger._entries = remaining_entries
```

The threading lock in `AuditExporter` guards concurrent access from the exporter's perspective, but `AuditLogger` itself doesn't know about this lock. If `AuditLogger.log_event()` is called concurrently with `apply_retention()`, the new entry could be appended to the old list reference that's about to be replaced, resulting in a lost entry. The GIL makes list append atomic in CPython, but the reference swap is not coordinated with the logger.

## Test coverage gaps

Not tested: callback exception handling in cost alerting (no test for a raising callback), concurrent `AuditLogger.log_event()` during `apply_retention()`, deprecated route behavior with non-trivial FastAPI signatures (path params, Depends).
