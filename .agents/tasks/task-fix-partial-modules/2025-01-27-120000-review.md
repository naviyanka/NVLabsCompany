# Five feature additions to adapters, triggers, knowledge, and evolution

This change adds five distinct features across unrelated subsystems: configurable polling and webhook callbacks to the HTTP adapter, stdin-based interactive messaging to the CLI adapter, a composable condition expression tree for the context trigger system, real-time collaboration primitives (subscribe/notify, locking) to Knowledge Plaza, and a `StatisticalFailureAnalyzer` subclass wiring significance testing to the existing failure analysis.

Watch for: `_stream_output` is defined but never called (confirmed), making the interactive stdin feature incomplete. The webhook callback router in `_handle_callback_result` uses a fragile first-match fallback when no `session_id` is in the payload (confirmed). The `_recent_changes` list in Knowledge Plaza grows without bound (confirmed). A failing subscriber callback in `notify_subscribers` blocks delivery to subsequent subscribers (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The HTTP adapter gains robust polling with configurable interval/max-polls/timeout and circuit-breaking on repeated connection failures, plus a webhook callback registration system. The callback routing has a design gap — when the incoming payload lacks a `session_id`, it falls back to matching the first non-expired registration, which is incorrect in any multi-session scenario.

The CLI adapter adds `send_message` for writing to a subprocess's stdin and `_stream_output` for reading stdout line-by-line. However `_stream_output` is never invoked anywhere — not in `_do_execute`, not spawned as a background task — so the interactive protocol is half-wired: you can send input but there's no mechanism consuming output in real time.

The condition expression system is a clean recursive evaluator over a frozen dataclass tree (And/Or/Not/Threshold/Time). The `ConditionBuilder` fluent API overwrites `_expression` on each call rather than composing, which means chained calls don't accumulate — only the last one wins. The `ThresholdCondition` evaluator raises raw `KeyError` on missing metrics and `TimeCondition` mixes naive/aware datetimes.

Knowledge Plaza adds in-memory pub/sub, page locking with auto-expiry, and a recent-changes feed. The subscriber notification loop is sequential with no exception isolation — one failing callback prevents the rest from receiving the event. The `_recent_changes` list is append-only with no eviction, and page locking is advisory-only (not enforced by `update_page`).

`StatisticalFailureAnalyzer` delegates to the existing `StatisticalAnalyzer` for significance testing, with a standalone confidence interval method that silently falls back to z=1.96 for unsupported confidence levels.

1. **Dead `_stream_output` method** — `_stream_output` in `cli_adapter.py` is defined but never called. Wire it into the subprocess lifecycle (e.g., as a background task in `_do_execute` when `is_interactive` is true) or remove it.

## Dead code in the interactive stdin protocol

`_stream_output` — the coroutine that reads stdout line-by-line — is never called. No part of `_do_execute` or any background task scheduler references it:

```python
async def _stream_output(
    self, process: asyncio.subprocess.Process, session_id: str
) -> None:
    # reads stdout line-by-line, appends to logs
```

Without a caller, interactive sessions have no way to surface process output until the process terminates and the existing `communicate()` call in `_do_execute` returns all buffered output at once. The `is_interactive` and `awaiting_input` flags are set in metadata but nothing transitions `awaiting_input` to `True` — it's initialized to `False` and only ever set back to `False` after `send_message`.

## Webhook callback routing ambiguity

`_handle_callback_result` first looks for `session_id` in `result_data`. If absent, it iterates `_callback_handlers` and picks the first registration that isn't expired:

```python
for sid, reg in self._callback_handlers.items():
    if reg.expiry and datetime.now(UTC) > reg.expiry:
        continue
    session_id = sid
    break
```

Dict iteration order in Python 3.7+ is insertion order, so with multiple active registrations this silently routes every session-id-less callback to the oldest registration. The test suite only exercises single-registration scenarios, so this isn't caught.

The registration is keyed by `session_id` rather than by callback URL or task ID, meaning a session can only have one callback at a time. If the external service doesn't echo `session_id` in its webhook payload (a common pattern), routing is broken for multi-session deployments.

## Knowledge Plaza memory and concurrency gaps

`_recent_changes` is a plain list that grows monotonically. In a long-running server handling thousands of page edits, this becomes a memory leak. `get_recent_changes` filters the full list on every call rather than pruning old entries.

`notify_subscribers` iterates callbacks sequentially:

```python
for _sid, callback in subscribers:
    if asyncio.iscoroutinefunction(callback):
        await callback(event)
    else:
        callback(event)
```

If any callback raises, the exception propagates and remaining subscribers never receive the event. A slow async callback also blocks delivery to all subsequent subscribers — there's no concurrency (e.g., `asyncio.gather`) or timeout.

Page locking is advisory: `lock_page` and `unlock_page` manage the `_page_locks` dict, but `update_page` never checks whether the page is locked by another agent. The lock API exists but enforcement is left entirely to callers with no documentation of this expectation.

## Condition expression evaluator edge cases

`ThresholdCondition` evaluation does a bare `context[expression.metric]` lookup — a missing key raises `KeyError` with no wrapping or user-friendly message. `TimeCondition` uses `datetime.now()` (naive) as the fallback when `current_time` is absent from context, while the `after`/`before` fields have type `datetime | None` with no timezone enforcement. Comparing a naive `now()` against a timezone-aware `after` value will raise `TypeError` at runtime.

The `ConditionBuilder` fluent API has a non-composing design: each method call overwrites `self._expression`. The docstring example shows `threshold(...).and_(...)`, which discards the threshold result. The intended use is to pass sub-expressions directly to `and_()` as arguments, but the builder-pattern naming implies incremental construction.

## StatisticalFailureAnalyzer silent fallback

`confidence_interval_for_rate` uses a hardcoded `t_critical` lookup table supporting confidence levels 0.90, 0.95, and 0.99. For any other value it silently falls back to z=1.96 (the 0.95 value), returning a confidence interval that doesn't match the requested confidence level. This should either reject unsupported levels or document the fallback behavior.
