# Five feature additions with review fixes applied

This change adds interactive stdin to the CLI adapter, webhook callbacks and robust polling to the HTTP adapter, a condition expression tree for context triggers, real-time collaboration primitives to Knowledge Plaza, and a `StatisticalFailureAnalyzer` combining root-cause analysis with significance testing. A follow-up commit (a359d25) addressed the six issues from the first review: `_stream_output` is now wired, the callback fallback removed, `_recent_changes` bounded, subscriber callbacks isolated, and docstrings clarified.

Watch for: `ThresholdCondition` raises raw `KeyError` on missing metrics with no wrapping (confirmed). `TimeCondition` uses naive `datetime.now()` as fallback, which will `TypeError` if `after`/`before` are timezone-aware (confirmed). The interactive `_do_execute` path awaits `process.wait()` with no mechanism for the caller to `send_message` unless execution is driven concurrently from a separate task — the usage protocol isn't documented (likely).

**Verdict**: APPROVED

## High-level view

The CLI adapter's interactive protocol is now complete: `_stream_output` runs as a background task consuming stdout while `_do_execute` awaits process exit, and `send_message` writes to stdin in the interim. The remaining gap is documentation: a caller must run `_do_execute` as a concurrent task to call `send_message`, and this concurrency contract isn't stated anywhere.

The HTTP adapter's webhook callback system now requires `session_id` in the incoming payload for routing, eliminating the ambiguous first-match fallback. Expired registrations are rejected and cleanup happens in `_do_terminate`.

The condition expression system provides a frozen-dataclass AST with a recursive evaluator. Two edge cases remain: `ThresholdCondition` raises `KeyError` if the metric isn't in context (rather than returning False or a descriptive error), and `TimeCondition` falls back to `datetime.now()` (naive) which will `TypeError` at comparison time if the `after`/`before` fields carry timezone info.

## Condition evaluator runtime errors on missing context

`ThresholdCondition` evaluation performs a bare dict lookup:

```python
metric_value = context[expression.metric]
comparator = _OPERATORS[expression.operator]
return bool(comparator(metric_value, expression.value))
```

If `expression.metric` isn't present in `context`, this raises `KeyError` with no indication of which condition failed or what metric was expected. In a condition tree with multiple thresholds composed via `AndCondition`, the first missing metric aborts the entire evaluation. There's no test for this case — all test contexts supply every referenced metric. Similarly, `_OPERATORS[expression.operator]` would raise `KeyError` on an invalid operator string, though the frozen dataclass defaults mitigate this in practice.

## TimeCondition timezone mismatch

The `datetime` import at the top of `context_trigger.py` is just `from datetime import datetime` — no `UTC` or `timezone` import. The fallback in `evaluate_condition`:

```python
now: datetime = context.get("current_time") or datetime.now()
```

produces a naive datetime. If a caller constructs `TimeCondition(after=datetime(2024, 1, 1, tzinfo=timezone.utc))`, the comparison `now <= expression.after` raises `TypeError: can't compare offset-naive and offset-aware datetimes`. The fix is `datetime.now(UTC)` but requires adding the import from `datetime`.

## Interactive session concurrency contract

The interactive path in `_do_execute`:

```python
await asyncio.wait_for(process.wait(), timeout=timeout)
```

occupies the caller's coroutine until the subprocess exits. For `send_message` to be useful, the caller must launch execution via `asyncio.create_task` and call `send_message` from a separate coroutine. The `send_message` docstring says "The process must be running" without explaining that `_do_execute` must be running concurrently for there to be a process to write to.
