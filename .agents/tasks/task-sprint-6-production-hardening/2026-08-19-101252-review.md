# Sprint 6: Production hardening — five features ported from munder-difflin

This sprint ports five subsystems from the TypeScript/Electron munder-difflin codebase into the Python/FastAPI NEXUS backend: a per-agent operator control registry with REST API, a memory auto-condenser with 3-region structure and verify gate, a file-backed knowledge store with BM25 search, a production-grade inbound webhook server, and a multi-agent graceful shutdown protocol. Each feature ships with comprehensive tests and clean type definitions.

Watch for: the `ClosingTimeController` defines `TIMEOUT_SECONDS` and `TEARDOWN_GRACE_SECONDS` constants but never enforces them — there is no timer or async watchdog that fires a TIMEOUT phase (confirmed). The `WebhookServer` accepts `WebhookEndpoint.enabled` in its type but never checks the field — disabled endpoints still serve traffic (confirmed). The `MemoryReflector.condense()` pipeline validates and rebuilds the file but never returns the rebuilt text to the caller, making it impossible to persist the result without re-running the pipeline (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The Control Registry exposes pause, gate, steer, halt, and resume via synchronous FastAPI endpoints backed by an in-process state machine. No concurrency concerns for the current single-worker model.

The Memory Reflector's `condense()` pipeline builds and verifies a rebuilt file, but only returns `ReflectResult` (a bool + byte counts) — the rebuilt text is discarded. The caller cannot persist the condensed file without re-invoking the LLM summarizer.

The Knowledge Graph's `_save_index` does a direct `open(..., "w")` + `json.dump` with no atomic write or file locking. Two near-simultaneous ingest calls can race and corrupt `index.json`.

The Webhook Server ignores the `enabled` field on `WebhookEndpoint` — `set_endpoints` registers anything with a non-empty id and secret. `LEGACY_ENDPOINT_ID` is defined but never wired into routing, suggesting incomplete porting.

The Closing Time Protocol defines `TIMEOUT_SECONDS` (360s) and `TEARDOWN_GRACE_SECONDS` (2.5s) but no code path consumes either. A stuck worker that never ACKs and never leaves the live list will hold the protocol open indefinitely.

## Closing Time: defined constants without enforcement

The protocol declares two timing constants that shape its documented behavior:

```python
TIMEOUT_SECONDS: float = 360
TEARDOWN_GRACE_SECONDS: float = 2.5
```

Neither is referenced by any logic in the module. The `ClosingTimePhase.TIMEOUT` enum value exists but no code path ever emits it. The `on_concluded` callback fires synchronously the instant the COMPLETE check passes — there is no 2.5s grace window for final writes to land on disk.

A stuck worker that never ACKs (and never leaves the live list) will hold the protocol open indefinitely. The original TypeScript implementation handled this via a `setTimeout` plus periodic tick; the Python port needs either an async timeout task, a `tick(now)` method the runtime event loop can drive, or integration with the existing `HeartbeatMonitor` to surface a timeout event.

## Memory Reflector: pipeline produces a result it cannot deliver

The `condense()` method runs the full pipeline — parse, evict, summarize, rebuild, verify — and the rebuilt file text exists as the local variable `rebuilt`. But the method only returns:

```python
return ReflectResult(
    id=agent_id,
    condensed=True,
    reason="condensed",
    old_bytes=old_bytes,
    new_bytes=new_bytes,
)
```

The `ReflectResult` dataclass has no field for the rebuilt content. The caller (presumably a background loop that reads `memory.md`, calls `condense()`, and writes the result back) cannot get the new file text without re-running the summarizer — which involves an LLM call.

The fix is either adding a `text: str | None` field to `ReflectResult`, or accepting a `write_fn: Callable[[str], None]` parameter that `condense()` invokes after verify passes.

## Webhook Server: `enabled` flag and legacy endpoint dead code

`set_endpoints` filters only on non-empty `id` and `secret`:

```python
for ep in endpoints:
    if ep.id and ep.secret:
        next_map[ep.id] = ep
```

An endpoint with `enabled=False` will be registered and serve traffic normally. The fix: add `and ep.enabled` to the condition.

`LEGACY_ENDPOINT_ID = "legacy"` is exported and documented as the target for bare `POST /` requests, but there is no code anywhere that maps a root-path POST to this endpoint ID. Dead code suggesting incomplete porting from the TypeScript source.

## Knowledge Graph: no atomicity on index writes

`_save_index` does a direct `open(..., "w")` and `json.dump`. If the process crashes mid-write (or two processes ingest simultaneously), `index.json` will be corrupted or one write will be lost. The idiomatic fix:

```python
import tempfile, os
with tempfile.NamedTemporaryFile(
    mode="w", dir=str(self._root_path), delete=False, suffix=".tmp"
) as tmp:
    json.dump(entries, tmp, indent=2)
    tmp_path = tmp.name
os.replace(tmp_path, str(self._index_path))
```

This gives crash-safe atomic replacement on POSIX.
