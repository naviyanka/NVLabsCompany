## High-level view

The `ClosingTimeController.tick(now)` method enforces `TIMEOUT_SECONDS` by recording the start time on first call and checking elapsed time on subsequent calls. The runtime event loop drives the clock. However, when timeout fires, `on_concluded` is not called — only the COMPLETE path invokes it. The runtime must observe `ClosingTimePhase.TIMEOUT` events independently to initiate forced teardown.

The `MemoryReflector` fix adds `rebuilt_text: str | None` to `ReflectResult` and populates it on the success path only. The field is `None` on failure paths, preventing callers from accidentally writing a partial result.

The webhook server's `set_endpoints` now gates on `ep.enabled`, and `handle_post` maps falsy `endpoint_id` to `LEGACY_ENDPOINT_ID` before entering the security pipeline.

The knowledge graph's `_save_index` uses `tempfile.mkstemp` (hidden-prefix temp file) + `os.replace` with cleanup on failure.

## tick() timeout: on_concluded asymmetry

The asymmetry between the COMPLETE and TIMEOUT paths:

```python
# COMPLETE path (on_routed):
self._emit_event(ClosingTimePhase.COMPLETE)
self._active = False
self._on_concluded()

# TIMEOUT path (tick):
self._active = False
self._emit_event(ClosingTimePhase.TIMEOUT)
# on_concluded is never called
```

A runtime integrating this controller would need to either poll `events` for TIMEOUT, or wrap `tick()` with its own timeout-to-teardown logic. The TypeScript original handled both paths through the same `onConcluded` callback. Whether this divergence is intentional should be confirmed — if it is, the `on_concluded` docstring should state it fires only on COMPLETE.

Additionally, the timeout clock starts on the first `tick()` call rather than on `start()`. If the runtime takes several seconds to begin its tick loop after `start()`, the effective timeout window exceeds 360s from the protocol's logical start. The `start()` method sets `_started_at = None` with a comment noting the caller or `tick()` will set it — a deliberate choice that puts clock ownership in the runtime's hands, but worth documenting for integrators.
